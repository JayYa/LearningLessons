架构与网络

术语含义
Origin
源		 协议 + 域名 + 端口 三者构成的元组。三者全同才算同源。http://localhost:5173 与 http://localhost:8000 不同源；localhost 与 127.0.0.1 也不同源。
CORS
跨源资源共享		 Cross-Origin Resource Sharing。服务端通过 Access-Control-Allow-Origin 等响应头，声明允许哪些源读取自己的响应。拦截动作发生在浏览器，服务端代码已执行完毕。非浏览器客户端（curl / Postman / 移动端）不受约束。MDN
Preflight
预检请求		 对于非简单请求（如带自定义头、PUT/DELETE），浏览器会先自动发一个 OPTIONS 请求问服务端“我能发吗”。这就是为什么 CORSMiddleware 里要配 allow_methods 和 allow_headers。
SPA
单页应用		 Single-Page Application。服务端只返回一个近乎空白的 HTML 外壳，之后由 JS 接管全部渲染与路由。与 Razor Pages / MVC 的服务端渲染相对。

工具链

术语含义
Dev server
开发服务器		 仅在开发期存在的进程（此处为 Vite），负责实时编译源码并交付给浏览器。不进生产环境。
HMR
热模块替换		 Hot Module Replacement。保存文件后，只把变更的模块推给浏览器并原地替换，页面不整体刷新、当前 state 得以保留。这是 dev server 存在的核心理由。
Transpile
转译		 把一种高级语言编译成另一种同层级的高级语言（TS → JS），而非编译成机器码或 IL。TS 编译器的产物仍然是人类可读的 JS。
Bundle
打包		 把成百上千个源文件与依赖合并、压缩成少数几个 .js 文件，减少浏览器的请求数。pnpm build 做的就是这件事。
venv
虚拟环境		 Python 的项目级依赖隔离机制。python -m venv .venv 创建一份独立的解释器与 site-packages；Activate.ps1 把它插到 PATH 最前面。.venv 不进版本库。
node_modules 包管理器安装依赖的落地目录，位于项目内。不进版本库，由 package.json + 锁文件（pnpm-lock.yaml）重建。pnpm 下它是一片指向全局 store 的链接，而非真实副本。

TypeScript 类型系统

术语含义
Structural typing
结构化类型		 类型之间的兼容性只看形状（有哪些属性、类型是什么），与名字、继承关系无关。TS 的默认规则。判定标准是「至少有」而非「刚好是」。
Nominal typing
名义类型		 兼容性看名字与声明的继承关系。C# / Java 的规则。两个结构相同但名字不同的 class 绝不互换。
TS 中的例外：带 private / protected 成员的 class 会按声明位置比较，等效于名义类型。
Reified
具化		 类型信息在运行时依然存在。C# 的类型是 reified 的（故有反射、is、typeof(T)）；TS 的类型不是。
Type erasure
类型擦除		 编译时把所有类型信息删除的过程。interface、type、类型注解、泛型参数编译后一个字节都不剩。运行时唯一残留的类型痕迹是 class（编译成真实的 JS 函数，故 instanceof 可用）。
Excess property check
多余属性检查		 把新鲜的对象字面量直接赋给某个类型时，TS 会额外禁止多余属性（TS2353）。先赋给变量再传则不触发。设计意图是抓拼写错误。
Type alias
类型别名		 type X = …。与 interface 高度重叠，但能给联合类型、原始类型等任意类型命名（type Id = string | number），interface 不能。
any / unknown 都表示「类型未知」。any 关闭检查，可以对它做任何事 —— 类型系统的逃生舱与主要漏洞来源（res.json() 就返回它）。unknown 是安全版：必须先收窄类型才能使用。

边界与校验

术语含义
Boundary
边界		 类型系统管辖权的国境线。线内编译器担保，线外什么都可能进来。典型边界：HTTP 请求/响应、localStorage、URL 参数、环境变量、第三方 SDK 回调。边界上的类型注解是承诺，不是检查，必须补运行时校验。
Pydantic Python 的运行时数据校验库，FastAPI 的底座。class X(BaseModel) 在类定义时读取类型注解，据此生成校验与序列化逻辑。对照 C#：一个类同时干了 DTO、模型绑定、校验、序列化四件事。文档
Response model
响应模型		 FastAPI 中写在路由返回类型注解上的 Pydantic 模型（def f() -> HelloResponse:）。它做三件事：校验（缺字段 → ResponseValidationError → 500）、过滤（多余字段静默剥离，防泄漏）、生成 OpenAPI schema。文档
422
Unprocessable Entity		 FastAPI 对请求体校验失败的默认响应码（不是 400）。此时路由函数根本没被调用。对照：响应体校验失败是服务端自己违约 → 500。4xx 是调用方的错，5xx 是服务端的错。
JSON Schema 用 JSON 描述 JSON 结构的标准。Pydantic 模型会被转成它，嵌进 OpenAPI 文档。它是前后端契约唯一可机读的形式 —— 前端据此自动生成 TS 类型的基础。
Zod TS 生态事实标准的运行时校验库。z.object({...}) 产生的是值（活到运行时），不是类型。文档
z.infer type T = z.infer<typeof Schema>，从 schema 反推出静态类型。方向与 C# 相反：schema（值）是单一事实来源，类型是它的投影。这样类型和校验规则不可能漂移。
typeof Schema 里的 typeof 是 TS 的类型运算符（取一个值的类型），和 JS 运行时的 typeof 只是同名。
parse / safeParse .parse() 失败时抛 ZodError；.safeParse() 不抛，返回 { success: true, data } 或 { success: false, error }。后者对应 C# 的 TryParse 模式，但不需要 out 参数。
Discriminated union
可辨识联合		 联合类型的各成员共有一个字面量字段作为标签（如 success: true | false）。判断该字段后，TS 自动知道是哪一支。safeParse 的返回值就是它。对照 C# 9 的 switch 模式匹配，但这里靠的是值而非类型。
Narrowing
类型收窄		 TS 通过控制流分析，在 if / typeof / in 等判断之后把变量类型缩小到更精确的一支。这是 unknown 变得可用的唯一途径。官方手册

Python

术语含义
Decorator
装饰器		 @something 语法。它是一个函数，接收被装饰的函数、返回一个新函数。@app.get("/x") 的作用是把下面的函数注册进路由表。语法位置像 C# 的 attribute，机制却完全不同 —— attribute 是编译期元数据，装饰器是运行时的函数调用。
Type hint
类型注解		 def f(x: int) -> str: 中的注解。Python 运行时不会据此做任何检查 —— 它纯粹是给工具看的元数据。FastAPI 和 Pydantic 的做法是在运行时主动读取这些注解并据此生成校验逻辑，这正是它们「看起来像静态类型语言」的原因。
ASGI Asynchronous Server Gateway Interface。Python 异步 Web 应用与服务器之间的标准接口。FastAPI 是 ASGI 应用，Uvicorn 是 ASGI 服务器，二者靠这个约定对接 —— 类比 ASP.NET Core 应用与 Kestrel 的关系。

React

术语含义
Render
渲染		 React 调用一次你的组件函数，拿到一份「界面应该长什么样」的描述。注意：渲染 ≠ 更新 DOM。描述算出来后，React 再去比对并决定真正要改哪些 DOM。
Declarative
声明式		 UI = f(state)：你描述「给定这个 state，界面该是什么样」，而不是一步步命令界面怎么变。与 WPF / WinForms 那种抓住控件对象改属性的命令式相对。
State
状态		 组件的记忆。普通局部变量不行的两个理由：跨渲染保不住（retain），且改了不会触发重新渲染（trigger）。useState 一次给你这两样。react.dev
Snapshot
快照		 本课程最重要的 React 概念。一次渲染里，state 是个不会变的常量。每次渲染产生全新一批 const 与全新一批闭包，所以 setTimeout 里读到的是「那一次渲染」的值。说它「异步」是错的 —— 等多久都不会变。react.dev
Updater function
更新函数		 setCount(c => c + 1) 里的 c => c + 1。它接收待处理的 state并算出下一个。判据：新值依赖旧值就用它；不依赖就直接传值。
Hook 以 use 开头、只能在组件（或自定义 hook）顶层调用的函数，用于接入 React 的状态与生命周期。React 内部为每个组件维护一个 state 数组 + 游标，每调用一次 hook 就取下一格并 +1。
Rules of Hooks
hook 规则		 不得在循环、条件、嵌套函数、try/catch/finally 里调用 hook，也不得在提前 return 之后调用。这不是风格约定，是上一条那个数据结构决定的。违反时的运行时报错：Rendered more/fewer hooks than…react.dev
Fragment <>...</>。JSX 必须返回单个根节点，Fragment 是一个不产生真实 DOM 元素的空壳包装，专用于满足这条规定。
Batching
批处理		 一次事件里的多次 setState 被合并成一次重新渲染。与「三次只加一」是两件事：那个讲的是算出什么值（快照），这个讲的是渲染几次。改成 updater 后数字变成 3，但组件函数仍只被调用一次。

React 的副作用

术语含义
Effect
副作用		 由渲染本身（而非某个特定事件）引起的副作用。判据是问「这段代码为什么要跑」：因为组件被显示出来了 → Effect；因为用户点了某个按钮 → 事件处理函数。不是生命周期钩子，官方的词是 synchronizing：把外部系统同步到当前 state。react.dev
Commit
提交		 React 把算出来的 UI 描述实际写进 DOM 的那一步。Effect 在 commit 之后、屏幕更新之后才跑。渲染 → commit → effect，这个顺序解释了为什么「用 Effect 算派生数据」会多出一轮渲染。
Dependency array
依赖数组		 三种形态：不写 = 每次渲染后都跑；[] = 只在挂载时；[a, b] = 挂载时 + a 或 b 变化时。「变了」用 Object.is 浅比较判定。
Cleanup function
清理函数		 effect return 出去的那个函数。React 在每次重新执行 effect 之前、以及组件卸载时调用它。配对口诀：connect ↔ disconnect，subscribe ↔ unsubscribe，fetch ↔ cancel 或 ignore。
StrictMode
严格模式		 开发模式下 React 故意把每个组件挂载后立刻重挂载一次，用来检验你的 cleanup 写对了没有。生产构建不会双跑。正确应对是补 cleanup，而不是删掉 <StrictMode>。判据：用户不应该能区分「跑一次」和「setup → cleanup → setup」。
Race condition
竞态		 两个请求同时在飞，返回顺序不保证。先点 Alice 再点 Bob，若 Alice 的响应后到，屏幕就是 Bob 的标题配 Alice 的数据。不报错、难复现。这是 cleanup 真正要防的东西，StrictMode 双跑只是让你提前发现它。
Object.is React 判断「变没变」用的唯一标尺，贯穿 state、依赖数组、memo。永远是浅比较，React 从不深比较。记住 {} !== {} —— await res.json() 每次都是新对象，这是 useEffect 无限循环的真正根因。
exhaustive-deps lint 规则：effect 里读到的每个响应式值都应申报进依赖数组。它是 warning，不是 error（pnpm lint 仍退出 0）。对比上一节的 Rules of Hooks 是 error —— 一个是纪律，一个是建议。
