C# ↔ Python / TypeScript 对照表

你已有的知识是杠杆。但每个类比都有裂缝，裂缝处才是面试真正考的东西。

怎么用这份表

「⚠ 裂缝」一列是重点。类比让你上手快，裂缝让你不在面试里露怯。当面试官问「你从 C# 转过来，觉得最不适应的是什么」，答案应该直接从这一列里取 —— 那是一道送分题。

后端框架概念

C# / ASP.NET CoreFastAPI⚠ 裂缝
[HttpGet("/api/x")] @app.get("/api/x") attribute 是编译期元数据，靠反射读取；decorator 是运行时执行的函数调用，直接修改/注册被装饰的对象。
Middleware 管道 app.add_middleware(...) 概念高度一致 —— 洋葱模型、顺序敏感。这是你可以直接迁移的知识。
DTO + 模型绑定
+ FluentValidation		 Pydantic BaseModel Pydantic 一个类同时干了 DTO、绑定、校验、序列化四件事，而且校验规则就写在类型注解里。
内置 DI 容器 Depends() FastAPI 没有全局容器和生命周期注册（singleton/scoped/transient）；依赖是在函数签名上按需显式声明的。这是个高频追问点。
async Task<T> async def 语法几乎一样，模型差别很大：Python 有 GIL，单进程内只有一个事件循环、无线程池并行。CPU 密集任务在 Python 里不能靠 async 解决。

类型系统（第 2 课）

C#TypeScript⚠ 裂缝
名义类型
（nominal）		 结构化类型
（structural）		 C# 看声明：没写 : IFoo 就不是 IFoo。TS 看形状：只要属性对得上就通过，无需任何声明关系。官方为 C#/Java 开发者写的说明
类型在运行时存在
（reified）		 类型被擦除
（erased）		 C# 有 GetType()、反射、泛型实化。TS 的类型在编译后完全消失，运行时一行都不剩，没有任何 TS 层面的反射。
interface interface / type 同名不同物。TS 的 interface 只是「形状约束」，可以描述函数、数组、任意对象，且无需被实现方知晓。
class Foo : IBar class Foo implements Bar TS 的 implements 什么也不建立。它只是请编译器帮你自查形状是否对得上；写不写都不影响这个类能被赋给谁。C# 里它是身份的一部分。
private 成员 private 成员 结构化规则的唯一例外。含 private/protected 成员的 class 按声明位置比较 —— 两个字段完全相同的类互不兼容（TS2322）。面试时补上这一句，比只说「TS 是结构化的」强得多。
反序列化时校验
（JsonSerializer + DTO）		 没有对应物 最大的裂缝。res.json() 返回 any，你写的返回类型只是一句承诺，运行时无人核对。跨边界的数据必须自己加运行时校验（Zod / Pydantic）。
