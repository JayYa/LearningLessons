Lesson 0001 · 约 50 分钟

两个进程，一根线

把 React + TypeScript 前端和 Python 后端同时跑起来，让它们说上第一句话 —— 并撞一次墙。

本课的收获

课程结束时你会有：两个正在运行的终端窗口、一个浏览器页面显示着来自 Python 的字符串、以及一次亲手撞上并解决 CORS 的经历。更重要的是，你能回答面试里那个几乎必问的开场题：“讲讲你这个项目的架构。”

一、先建立心智模型：为什么是两个进程

这是你作为 C# 开发者进入这个技术栈时，第一个需要重装的直觉。

你熟悉的世界

在 ASP.NET Core MVC / Razor Pages 里，dotnet run 启动一个进程。这个进程既产出 HTML（服务端渲染 Razor 视图），又处理 /api/* 的数据请求，还托管 wwwroot 里的静态文件。一个进程、一个端口、一个 origin。

在 React + Python 的组合里，开发时是两个独立进程，互相完全不知道对方的存在：

进程启动命令默认端口它的唯一职责
前端
Vite dev server		 npm run dev 5173 把 .tsx 编译成浏览器能跑的 JS，通过 HTTP 交付给浏览器，并在你保存文件时热更新。它不碰你的业务数据。
后端
FastAPI / Uvicorn		 fastapi dev main.py 8000 接收 HTTP 请求，返回 JSON。它不知道 React 的存在，对它来说调用方是浏览器、curl 还是手机 App 没有区别。

连接两者的“一根线”，是浏览器里 React 代码发出的一次 fetch() 调用 —— 一个从 localhost:5173 页面发往 localhost:8000 的普通 HTTP 请求。整套架构的耦合点只有这一处：HTTP 上的 JSON 契约。

类比失效处 · 面试考点

不要说“Vite 是我的 Web 服务器”。Vite dev server 只在开发时存在。上线时你执行 npm run build，得到一堆静态 .html/.js/.css 文件，Vite 进程就消失了 —— 那些文件由 Nginx、CDN 或后端框架托管。这条“开发时两进程、生产时前端退化为静态文件”的认知，能立刻把你和只跟过教程的人区分开。Vite 构建文档

二、动手：从零到联通

逐条做，勾掉。进度会存在浏览器里，中断了也不丢。全部命令在 PowerShell 中执行。

  1. 建立项目骨架 
    cd d:\teach\Python-React-Typescript
mkdir playground\backend
cd playground

    我们把练手代码放在 playground/，和课程文档分开。

  2. 后端：建立虚拟环境 
    cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1

    提示符前面出现 (.venv) 就对了。.venv 是这个项目独占的 Python 与依赖副本。

    对照

    C# 没有真正的对应物 —— NuGet 包默认装在全局缓存里，由 .csproj 决定引用哪些。Python 的 pip 默认装到全局，两个项目要求不同版本的同一个库就会打架。venv 就是为了解决这个而存在的：把依赖关在项目目录里。venv 官方文档

  3. 安装 FastAPI 并写下 10 行后端 
    pip install "fastapi[standard]"

    装完后，在 backend\main.py 写入：

    from fastapi import FastAPI

app = FastAPI()

@app.get("/api/hello")
def hello() -> dict[str, str]:
    return {"message": "Hello from Python"}

    注意 @app.get(...) —— 这是 Python 的 decorator，作用上非常接近 C# 的 [HttpGet("/api/hello")] attribute。（机制上差别很大，那是后面某一课的内容。）

  4. 跑起来，然后去看白送的 Swagger 
    fastapi dev main.py

    浏览器打开 http://127.0.0.1:8000/api/hello 看到 JSON，再打开 http://127.0.0.1:8000/docs。

    停下来想三十秒

    那份 Swagger UI 你一行配置都没写。FastAPI 是从你写的类型注解（-> dict[str, str]）反推出 OpenAPI schema 的。这正是 FastAPI 对 C# 开发者最亲切的地方 —— 和 ASP.NET Core 用 Minimal API + Swashbuckle 的思路一致。FastAPI 特性说明

    让这个终端保持运行。 开一个新终端做下一步。

  5. 前端：脚手架 + 启动 
    cd d:\teach\Python-React-Typescript\playground
npm create vite@latest frontend -- --template react-ts
cd frontend
npm install
npm run dev

    打开 http://localhost:5173，应该看到 Vite + React 的默认页面。

    --template react-ts 中的 ts 是关键：它生成的是 .tsx 文件并配好 tsconfig.json。Vite 指南

  6. 拉起那根线（这一步会失败，这是设计好的）

    把 frontend\src\App.tsx 的全部内容替换为：

    import { useEffect, useState } from "react";

export default function App() {
  const [message, setMessage] = useState("加载中…");

  useEffect(() => {
    fetch("http://127.0.0.1:8000/api/hello")
      .then((res) => res.json())
      .then((data) => setMessage(data.message))
      .catch((err) => setMessage("失败：" + err.message));
  }, []);

  return <h1>{message}</h1>;
}

    保存。页面会自动刷新（这就是 HMR）。按 F12 打开浏览器控制台。

    你会看到一条红色报错，关键词是 CORS policy 与 No 'Access-Control-Allow-Origin' header。

    先别修。 请读完下面第三节，再回来做最后一步。

  7. 修好它

    在 backend\main.py 中，app = FastAPI() 那一行之后插入：

    from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_methods=["*"],
    allow_headers=["*"],
)

    后端会自动重载（fastapi dev 带热重载）。刷新前端页面 —— 应该显示 Hello from Python。

    你做到了

    屏幕上那行字，是 Python 生成的、经 HTTP 传输、由 TypeScript 接收、被 React 渲染出来的。这就是整套技术栈的完整回路。

三、你撞的那堵墙：CORS

这是新手最常见的第一个坑，也因此是高频面试题。三句话讲清：

  1. Origin（源）= 协议 + 域名 + 端口。http://localhost:5173 和 http://127.0.0.1:8000 端口不同（域名其实也不同），所以是两个不同的源。
  2. 浏览器默认禁止页面读取跨源响应，这叫同源策略。它防的是：你登录了银行网站，然后打开一个恶意页面，该页面用你的 cookie 偷偷调银行 API 并读取结果。
  3. CORS 是服务端的放行声明。后端在响应里加上 Access-Control-Allow-Origin: http://localhost:5173，等于告诉浏览器“这个源可以读我”。CORSMiddleware 干的就是加这个响应头。
最容易答错的细节

请求确实发出去了，后端也确实执行了。是浏览器在收到响应后，检查响应头，发现没有放行声明，于是拒绝把内容交给你的 JS 代码。所以 CORS 不是安全防护 —— curl、Postman、任何非浏览器客户端都不受它约束。这也是为什么你在写 C# 后端时很少遇到它：MVC 页面和 API 同源，压根不跨。MDN: CORS

四、检验一下

测验 1 / 3

开发时同时跑着 Vite（5173）与 FastAPI（8000）。两者的分工是？

Vite dev server 只做一件事：把源码编译好交给浏览器，并在文件变动时热更新。它对你的业务数据一无所知。FastAPI 只做一件事：收 HTTP 请求、返 JSON。两者唯一的联系是浏览器发出的那次 fetch。

测验 2 / 3

前端报 CORS 错误时，实际发生了什么？

后端的函数已经跑完并返回了响应。是浏览器在最后一步检查 Access-Control-Allow-Origin 响应头，发现没有放行，才拒绝把结果交给 JS。推论：如果你用 curl 请求同一个地址，会成功 —— 这是一个很好的排错手段，也是面试时能顺口说出的加分细节。

测验 3 / 3

Python 项目里的 .venv 目录，本质上是什么？

pip 默认把包装到全局解释器里，于是两个项目要求同一个库的不同版本时会冲突。venv 创建一份独立的解释器与 site-packages，Activate.ps1 只是把它插到 PATH 最前面。.venv 永远不进 Git —— 它对应的是 node_modules，不是 packages.config。

回忆练习 · 不要跳过

合上这一页，出声回答：开发的时候，为什么不干脆把 React 编译好的文件直接丢进 FastAPI 的静态目录，一个进程搞定？

因为会失去 HMR（热模块替换）：Vite dev server 会在你保存 .tsx 的瞬间把变更推给浏览器，页面局部更新且保留当前 state。走“编译到静态目录”的路子，每改一行都要重新完整构建。

关键补充：到了生产环境，“一个进程搞定”恰恰是常见做法之一 —— npm run build 产出静态文件，交给 Nginx / CDN，或者确实塞进后端托管。开发与生产的部署形态不同，这本身就是一个值得在面试中主动讲出来的点。

五、面试回答模板

如果面试官问：“讲讲你那个项目的架构”

“前后端分离。前端是 React + TypeScript，用 Vite 做构建工具；后端是 Python 的 FastAPI，只提供 JSON API。开发时是两个进程：Vite dev server 跑在 5173 提供前端资源和热更新，FastAPI 跑在 8000 提供接口，两者之间就是 HTTP 上的 JSON 契约。因为跨源，后端要配 CORS 放行前端的 origin。上线时前端 build 成静态文件由 Nginx 或 CDN 托管，Vite 进程本身不进生产环境。”

这段话之所以可信，是因为其中每一句你都亲手验证过。把 playground/ 留着 —— 后续每一课都在它上面加东西，最后它就是你能在面试中描述的那个项目。
