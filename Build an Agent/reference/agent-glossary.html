Agent 核心概念速查表

本术语表是 Agent 开发的"压缩字典"——每个术语的精确定义和它在代码中的对应物。持续更新。

Agent（智能体）
一个能够自主感知环境、做出决策、调用工具并执行多步任务的 AI 系统。由一个 LLM + 工具集 + 记忆 + 执行循环（Agent Loop）组成。
对比：聊天机器人 = 单轮问答；Agent = 多步自主执行。
Agent Loop（Agent 循环）
驱动 Agent 运行的反馈循环：感知输入 → LLM 推理 → 调用工具(可选) → 获取结果 → 继续推理 → 生成最终输出。循环终止条件是 LLM 判断任务已完成或达到退出条件。
同义：ReAct Loop（Reasoning + Acting）。
LLM（Large Language Model / 大语言模型）
Agent 的决策中枢。接收「任务描述 + 对话历史 + 可用工具列表 + 工具执行结果」，输出「该调用哪个工具」或「最终回复」。LLM 不做实际动作，只做推理决策。常用模型：GPT-4o、Claude Opus、Gemini 等。
Tool / Plugin（工具 / 插件）
可以被 Agent 调用的外部函数或 API，是 Agent 与外部世界交互的接口。在 Semantic Kernel 中通过 [KernelFunction] 定义，在 OpenAI 中叫 Function Calling。
同义：Function、Plugin、Skill、Action。
Function Calling（函数调用）
LLM 的一种能力——模型不直接执行函数，而是输出一个结构化的函数调用请求（函数名 + 参数 JSON），由框架负责实际执行。这是 Agent 能"做事"的关键机制。
注意：OpenAI 用这个术语，Anthropic 叫 Tool Use，本质相同。
Memory / Context（记忆 / 上下文）
Agent 的信息存储机制，分两层：
· 短期记忆 = 对话历史（ChatHistory），Agent 通过上下文窗口"记住"当前会话
· 长期记忆 = 向量数据库 + 语义检索（RAG），Agent 可以跨会话检索知识
关键约束：LLM 的上下文窗口有 token 上限，需要管理策略。
RAG（Retrieval-Augmented Generation / 检索增强生成）
在调用 LLM 之前，先从外部知识库检索相关文档，将文档注入 Prompt 再让 LLM 回答。解决 LLM 知识过时、幻觉、私有知识三大问题。
流程：查询 → Embedding → 向量检索 → 拼入 Prompt → LLM 生成。
Semantic Kernel (SK)
Microsoft 开源的 AI Agent 编排框架（C# / Python / Java），核心概念：Kernel（编排引擎）、Plugins（工具）、Memory（记忆）、Agents（ChatCompletionAgent 等）。对 C# 开发者是自然选择。
⚠️ 2026 年 4 月起进入维护模式，其 Agent 构建功能已被 Microsoft Agent Framework 正式继承和取代。SK 仍适合学习 Agent 内部机制（API 更透明），但新项目应优先考虑 MAF。
Microsoft Agent Framework (MAF)
Semantic Kernel 的正式继任者（v1.0 GA: 2026.4），融合了 SK 的企业工程基础与 AutoGen 的多 Agent 编排研究。核心变化：
· 统一 Agent 类型——chatClient.AsAIAgent(instructions)
· 原生基于 Microsoft.Extensions.AI（IChatClient）
· 多 Agent 是一等公民（群聊、Handoff、Magentic-One）
· 内置 MCP + A2A 支持、OpenTelemetry 链路追踪
· NuGet: Microsoft.Agents.AI；PyPI: agent-framework
本课程前几课用 SK 教学（API 更透明），后续迁移到 MAF。迁移指南见 learn.microsoft.com。
Kernel
Semantic Kernel 的中央编排器。管理 AI 服务连接、注册 Plugins、协调 Agent 执行。每个 Agent 关联一个 Kernel 实例。
类比：ASP.NET 的 Host/ServiceCollection。
ChatHistory
Semantic Kernel 中存储完整对话记录的数据结构。每次 Agent 调用时，ChatHistory 被序列化为 LLM 的消息数组（System + User + Assistant + Tool）。
关键操作：Add、序列化、截断（防止超出 token 限制）。
Instructions / System Prompt（系统指令）
定义 Agent 角色、行为边界和工具使用规则的提示词。在 Semantic Kernel 中通过 ChatCompletionAgent.Instructions 设置。它是 Agent 的"性格"和"道德准则"。
写好 Instructions 是 Agent 工程最重要的技能之一。
ReAct（Reasoning + Acting）
最基础的 Agent 模式：LLM 交替进行推理（思考下一步）和行动（调用工具）。每个推理步骤基于前一次行动的结果。90% 的 Agent 应用都基于此模式。
对比：Plan-and-Execute（先规划好全部步骤再执行）。
Multi-Agent（多 Agent 系统）
多个 Agent 分工协作完成复杂任务的架构。每个 Agent 有独立的 Instructions 和工具集，Agent 间通过共享消息或以层级调用协作。常见模式：Group Chat、Delegation、Debate。
Semantic Kernel 支持：AgentGroupChat、SelectionStrategy、TerminationStrategy。
MCP（Model Context Protocol）
Anthropic 提出的Agent-to-Tool 标准协议。定义统一的工具发现、调用、认证接口，让任何 Agent 能使用任何 MCP Server 提供的工具。
2025 年成为行业标准，Microsoft 已将 MCP 集成到 Semantic Kernel。
Token（令牌）
LLM 处理文本的最小单位——不是字也不是词。英文 ~0.75 词/token，中文 ~1-2 字/token。关键在于：token 有数量上限（上下文窗口）和按量计费（in + out tokens）。
Agent 开发的核心约束之一：长对话 = 更多 tokens = 更贵且可能超出窗口。
Temperature
控制 LLM 输出随机性的参数（0~2）。0 = 确定性（相同输入→相同输出），2 = 高随机性。Agent 的工具选择阶段建议低 temperature（0~0.3），创意生成阶段可以更高。
不是所有场景都该用默认值——根据步骤而非整个 Agent 调整。
