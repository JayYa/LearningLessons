YAML 基础语法

Compose 和 Kubernetes 的配置文件都是 YAML。本页只讲这两者用得到的子集——够写、够读、够排错。

一句话

YAML 只有三种结构：标量（一个值）、映射（键: 值）、序列（- 项）。三者可以任意嵌套，嵌套靠缩进表示。

三种结构

结构写法等价 JSON
标量image: nginx{"image": "nginx"}
映射（map）environment:
  POSTGRES_DB: shop
  POSTGRES_PASSWORD: secret		{"environment": {"POSTGRES_DB": "shop", "POSTGRES_PASSWORD": "secret"}}
序列（list）ports:
  - "8080:8080"
  - "5432:5432"		{"ports": ["8080:8080", "5432:5432"]}
序列里放映射volumes:
  - type: volume
    source: pgdata
  - type: bind
    source: ./cfg		{"volumes": [{"type":"volume","source":"pgdata"}, {"type":"bind","source":"./cfg"}]}
行内写法（flow style）test: ["CMD-SHELL", "pg_isready"]
labels: {app: api, tier: web}		就是 JSON。YAML 是 JSON 的超集，短列表常这么写

缩进规则

  • 只能用空格，不能用 Tab。Tab 直接报错。
  • 同一层级的键，缩进必须一致。常用 2 空格，多少个不重要，一致才重要。
  • - 后面的内容算作新的一层：- type: volume 下一行的 source: 要和 type 对齐（即比 - 多缩 2 格）。
  • 空行和缩进无关，可以随便加。

标量类型：什么时候要引号

YAML 会猜一个不带引号的值是什么类型。猜错了就出 bug，所以规则是：拿不准就加引号。

你写的YAML 理解为要字符串就写
8080整数"8080"
3.14、1e3浮点数"1e3"
true / false布尔。K8s 的 env value 必须是字符串，写 "true""true"
yes / no / on / offYAML 1.1 解析器当布尔（有名的"挪威问题"：国家代码 NO 变成 false）"no"
null、~、什么都不写空值。pgdata: 后面留空 = pgdata: null，Compose 靠这个表示"用默认设置""null"
22:22YAML 1.1 解析器当六十进制整数 1342；1.2 不会。Compose v2 不会，但习惯加引号"22:22"
0755八进制 493。K8s 的 defaultMode 常踩写十进制 493 或 "0755"看字段要求
a: b: c报错（值里有 : ）"b: c"
Host=db;Port=5432字符串，没问题——= ; 不是特殊字符不用引号
以 * & ! % @ ` [ { 开头YAML 特殊符号，报错或误解析加引号
# 注释从 # 到行尾是注释（前面要有空格）。值里要含 # 就加引号"a #b"

单引号 vs 双引号

  • '单引号'：里面什么都不转义，只有 '' 表示一个 '。
  • "双引号"：支持 \n \t \" 等转义。
  • Compose 的 ${VAR} 插值在两种引号里都生效（插值是 Compose 做的，不是 YAML）。

多行字符串

command: |
  echo one
  echo two          # | 保留换行 → "echo one\necho two\n"

description: >
  这是一段很长的话
  会被折成一行        # > 把换行折成空格 → "这是一段很长的话 会被折成一行\n"

K8s 的 ConfigMap 里塞整个配置文件、脚本时，几乎都用 |。

多文档与锚点

# --- 分隔多个文档。K8s 常把 Deployment + Service 放一个文件
apiVersion: apps/v1
kind: Deployment
---
apiVersion: v1
kind: Service
# & 定义锚点，* 引用，<<: 合并。Compose 里偶尔用来去重
x-common: &common
  restart: unless-stopped
  logging: {driver: json-file}

services:
  api:
    <<: *common
    image: hello-api:1.2

Compose 允许顶层任何 x- 开头的键作为"扩展字段"，专门放这种复用片段。K8s 不支持锚点合并（kubectl 会解析锚点，但风格上不用）。

排错清单

  1. yaml: line N: … → 先看第 N 行和上一行的缩进是否对齐、有没有 Tab。
  2. mapping values are not allowed in this context → 某个值里有 : （冒号+空格），加引号。
  3. did not find expected key → 缩进层级错了，通常是某行多/少了 2 格。
  4. 值"类型不对"（期望 string 得到 bool/int） → 加引号。
  5. Compose：docker compose config 打印解析后的结果，看它理解成了什么。K8s：kubectl apply --dry-run=client -f x.yaml。
