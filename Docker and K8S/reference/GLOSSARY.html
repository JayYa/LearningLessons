术语表

课程中所有术语的唯一权威定义。每节课都遵循这里的措辞。术语一律保留英文原词。

Docker

术语定义
Dockerfile一个纯文本配方，一行一条指令，描述如何造出一个 image。它本身不是 image。↗ 官方参考
image（镜像）只读的模板：文件系统快照 + 启动时该跑什么命令的元数据。类比：程序的安装包 / 类（class）。
container（容器）image 的一个运行实例，带一层可写层。类比：进程 / 对象（instance）。一个 image 可以起很多 container。
layer（层）Dockerfile 中大多数指令各产生一层文件系统增量。层可缓存、可跨 image 共享 —— 这是构建快慢的关键。
base imageFROM 指定的起点 image，例如 nginx:alpine。↗
tag（标签）image 的人类可读名字，格式 name:version，如 myapp:1.0。省略版本时默认 :latest（这只是个普通标签，不代表"最新"）。
registry（仓库）存放和分发 image 的服务器，如 Docker Hub、GHCR、私有 Harbor。push 上传、pull 下载。
build contextdocker build 末尾那个路径（常见是 .）。COPY 只能取到 context 里的文件。BuildKit 只传输 COPY/ADD 实际引用的路径；COPY . . 时才是整个目录，.dockerignore 在那时起作用。
stage（阶段）Dockerfile 里每个 FROM 开启一个阶段，FROM x AS 名字 可命名。最终镜像只含最后一个阶段；前面阶段的文件要靠 COPY --from=名字 显式带过去。用于"SDK 编译、runtime 运行"的多阶段构建。↗ 官方参考
ARG vs ENVARG：构建期变量，--build-arg 传入，只在声明它的阶段可见，不进容器。ENV：写进镜像元数据，容器进程能读到，运行期可用 -e 覆盖。
layer cache（层缓存）某一层的指令与输入都没变则直接复用（显示 CACHED）；一旦某层失效，它之后的所有层一并重建。所以少变的（依赖清单）放前面，多变的（源码）放后面。
port mapping-p 主机端口:容器端口。容器有自己的网络命名空间，不映射就无法从 Windows 侧访问。
volume（卷）容器外的持久化存储。容器删掉数据就没了，除非放在 volume 或 bind mount 里。

Kubernetes

术语定义
PodK8s 里最小的可调度单元：一个或多个共享网络与存储的 container。你不直接管 Pod，由控制器管。
Deployment声明"我要 N 个这样的 Pod 一直跑着"的控制器，负责创建、伸缩、滚动更新和回滚。↗
Service给一组会变动的 Pod 提供一个稳定的访问入口（固定名字 + 虚拟 IP）。
kubectl与集群通信的命令行工具。↗ 速查表
manifest描述期望状态的 YAML 文件。kubectl apply -f 提交给集群。
声明式（declarative）K8s 的核心心智模型：你描述想要的最终状态，控制器不断把现实拉向它。而不是下达一步步的命令。
