常用子命令（在 compose.yaml 所在目录执行）

命令做什么
docker compose up -d创建/更新并启动。改了 YAML 或 .env 再跑一次 → 只重建受影响的服务
docker compose ps本项目的容器、状态、健康、端口
docker compose logs -f api看某服务日志（不写服务名 = 全部）
docker compose exec db psql -U postgres在运行中的服务里执行命令。用服务名，不是容器名
docker compose config打印插值、合并后的最终 YAML。"配置没生效"第一步看它
docker compose down删容器 + 网络。留 named volume
docker compose down -v连 named volume 与匿名卷一起删。数据没了
docker compose pull / build只拉镜像 / 只构建，不启动
docker compose restart api重启一个服务（不重新读 YAML；改了配置要用 up -d）

变量插值与优先级

# compose.yaml
environment:
  Greeting: ${GREETING:-默认值}        # 没设就用默认值
  Secret:   ${DB_PASSWORD:?必须设置}   # 没设就报错退出

# .env（与 compose.yaml 同目录，自动读取，只参与插值）
GREETING=Hello from .env!

容器里最终看到的值，高优先级在上（官方表）：

  1. docker compose run -e K=V
  2. shell 环境变量 / .env 经插值填进 environment: 的值
  3. environment: 里写死的值
  4. env_file: 文件里的值
  5. 镜像 ENV

.env ≠ env_file:。前者替换 YAML 里的 ${…}，后者把文件内容直接喂给容器。
