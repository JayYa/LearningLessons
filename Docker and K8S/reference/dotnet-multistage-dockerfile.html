.NET 多阶段 Dockerfile 模板

新项目直接抄这份，改三处：项目名、.NET 版本、端口。每一行的理由写在右侧。

模板（单项目 Web API）

# ---------- 阶段 1：构建（用完即弃） ----------
FROM mcr.microsoft.com/dotnet/sdk:9.0 AS build
ARG BUILD_CONFIGURATION=Release
WORKDIR /src

# 先只复制依赖清单，单独 restore —— 让这层缓存尽量长命
COPY MyApi.csproj .
RUN dotnet restore

# 再复制全部源码并发布（--no-restore：上面已经 restore 过）
COPY . .
RUN dotnet publish -c $BUILD_CONFIGURATION -o /app --no-restore

# ---------- 阶段 2：运行（最终镜像 = 只有这一段） ----------
FROM mcr.microsoft.com/dotnet/aspnet:9.0
WORKDIR /app
COPY --from=build /app .
EXPOSE 8080
ENTRYPOINT ["dotnet", "MyApi.dll"]

配套 .dockerignore（放在 Dockerfile 同目录）：

bin/
obj/
.git/
.vs/
**/*.user

逐行理由

行为什么这么写
FROM sdk AS build编译需要 SDK（1.24 GB）。AS build 给阶段命名，供后面 --from=build 引用。
ARG BUILD_CONFIGURATION构建期变量，--build-arg BUILD_CONFIGURATION=Debug 可覆盖。只在本阶段可见，不进容器。
COPY *.csproj → restore层缓存规则：某层输入变了，它及其后所有层重建。csproj 少变、源码多变，所以把 restore 绑在 csproj 上，改代码时可跳过。
COPY . .此时才把全部源码送进来。.dockerignore 在这一步起作用，排除 bin/obj 避免污染和无谓传输。
publish -o /app --no-restore产物集中到 /app，方便下一阶段一次性拿走。
FROM aspnet运行只需 ASP.NET runtime（329 MB）。控制台程序用 runtime；极致体积用 runtime-deps + self-contained。
COPY --from=build /app .跨阶段复制。只有这一行把 build 阶段的东西带进最终镜像，其余全部丢弃。
EXPOSE 8080纯元数据。.NET 8+ 默认监听 8080，写在这里是给人看的。真正映射靠 docker run -p。
ENTRYPOINT ["dotnet", "MyApi.dll"]exec 形式；用 ENTRYPOINT 而非 CMD，表示"这个镜像就是这个程序"。docker run 镜像 --urls ... 会作为参数追加。

常见变体

场景改法
多项目解决方案build 阶段 context 设为解决方案根目录；先 COPY *.sln . 与各 COPY src/X/X.csproj src/X/，再 restore；publish 指定入口项目路径。
只构建到某阶段（调试）docker build --target build -t myapi:build .
非 root 运行最终阶段加 USER $APP_UID（.NET 8+ 官方镜像内置该用户）。
改监听端口不改 Dockerfile，运行期 -e ASPNETCORE_HTTP_PORTS=80。
不写 Dockerfiledotnet publish /t:PublishContainer，见 publish configuration。

实测数字（2026-09，Docker Desktop）：单阶段 sdk 镜像 1.24 GB；多阶段 aspnet 镜像 329 MB；改一行 .cs 重建，restore 命中 CACHED，publish 约 4 s。
