层内容

环境

问题答案
未设置时Production
本机 dotnet run读 Properties/launchSettings.json 第一个 commandName:"Project" profile 的 environmentVariables + applicationUrl；覆盖系统环境变量
绕过 launchSettingsdotnet run --no-launch-profile；或 dotnet run -e Staging；或 -lp https 选 profile
发布后launchSettings.json 不部署；只看环境变量 / 命令行
两个变量都设WebApplication 下 DOTNET_ENVIRONMENT > ASPNETCORE_ENVIRONMENT（老 WebHost 相反）
代码里定WebApplication.CreateBuilder(new WebApplicationOptions { EnvironmentName = Environments.Staging })
判断builder.Environment（Build 前可用）/ app.Environment：IsDevelopment() IsStaging() IsProduction() IsEnvironment("Testing")

配置加载顺序（后者覆盖前者）

appsettings.json → appsettings.{Env}.json → User Secrets（仅 Dev） → 环境变量 → 命令行

端口 / URL

方式示例
launchSettings.json"applicationUrl": "https://localhost:7052;http://localhost:5249"
环境变量（首选）ASPNETCORE_URLS=http://*:3000;https://+:5000
命令行dotnet run --urls http://localhost:5100
仅端口ASPNETCORE_HTTP_PORTS=8080（ASPNETCORE_URLS 存在时被其覆盖）
代码app.Run("http://localhost:3000") / app.Urls.Add(…)
默认http://localhost:5000（+ https://localhost:5001）；本机 4904–5003 被 Windows 保留，5000 会绑定失败
