Channel<T>：创建

API用途注意
Channel.CreateBounded<T>(capacity)默认选择满时 Wait（背压）
Channel.CreateBounded<T>(new BoundedChannelOptions(n) { ... })定制满时策略见下表
Channel.CreateUnbounded<T>()生产量有天然上限时否则内存无限涨
Channel.CreateUnboundedPrioritized<T>()按优先级出队（.NET 9+）T 需可比较或传 Comparer
BoundedChannelOptions含义
FullMode = Wait满时 WriteAsync 异步等待（默认，背压）
FullMode = DropOldest丢最旧的，写入新的
FullMode = DropNewest丢队尾最新的，写入新的
FullMode = DropWrite丢掉正要写的这条（TryWrite 返回 false）
SingleReader / SingleWriter = true承诺单读/单写 → 无锁快路径。违反承诺不报错但行为未定义
AllowSynchronousContinuations默认 false。true 时 reader 的续体可能在 writer 线程上同步跑——快但危险

Channel<T>：读写

// Writer
await writer.WriteAsync(item, ct);        // Bounded 满时等待
bool ok = writer.TryWrite(item);          // 不等；满/已关闭 → false
await writer.WaitToWriteAsync(ct);        // true = 有空位；false = 已 Complete
writer.Complete();                        // 结束；重复调用抛，用 TryComplete 更稳
writer.TryComplete(ex);                   // 带异常结束 → 消费者 ReadAllAsync 抛 ex

// Reader
await foreach (var x in reader.ReadAllAsync(ct)) { }   // 推荐；Complete 后排空自动退出
while (await reader.WaitToReadAsync(ct))               // 手动 drain 模式
    while (reader.TryRead(out var x)) { }
var x = await reader.ReadAsync(ct);       // 已 Complete 且空 → ChannelClosedException
await reader.Completion;                  // Task：Complete 且排空后完成（带异常则 faulted）
reader.Count / reader.CanCount            // 不是所有实现都支持

Channel 接 Host 的模板

var ch = Channel.CreateBounded<Job>(new BoundedChannelOptions(100) { SingleReader = true });
builder.Services.AddSingleton(ch.Reader);            // 消费者只依赖 ChannelReader<Job>
builder.Services.AddSingleton(ch.Writer);            // 生产者只依赖 ChannelWriter<Job>
builder.Services.AddHostedService<Consumer>();      // 先注册 → 后关闭
builder.Services.AddHostedService<Producer>();      // 后注册 → 先关闭，finally { writer.Complete(); }

// Producer.ExecuteAsync
try   { while (...) await writer.WriteAsync(job, stoppingToken); }
catch (OperationCanceledException) { }
finally { writer.Complete(); }

// Consumer.ExecuteAsync —— 不传 stoppingToken 则排空后退出；传了则关闭时立即丢弃余量
await foreach (var job in reader.ReadAllAsync()) await Handle(job);
⚠️ 关闭顺序 = 注册倒序（LIFO）。消费者要排空就必须先注册。余量处理时间受 HostOptions.ShutdownTimeout（默认 30 秒）约束。

多消费者

// N 个消费者共享一个 Reader：每条只被一个消费者拿到，顺序【不】保证
var workers = Enumerable.Range(0, 4).Select(_ => Task.Run(async () =>
{
    await foreach (var job in reader.ReadAllAsync(ct)) await Handle(job);
}));
await Task.WhenAll(workers);
// 要保序 → 一个消费者；要保序又要并行 → 按 key 分片到多个 Channel

PeriodicTimer

using var timer = new PeriodicTimer(TimeSpan.FromSeconds(5));
while (await timer.WaitForNextTickAsync(stoppingToken))   // 取消 → OperationCanceledException；Dispose → false
    await DoWorkAsync(stoppingToken);
timer.Period = TimeSpan.FromSeconds(10);                   // .NET 8+ 运行时可改
语义说明
不重叠tick 只在 await WaitForNextTickAsync 时交付；循环体跑多久都不会并发第二次
tick 合并循环体超过周期，错过的多个 tick 合并成一个（下一次 await 立即返回 true）
单等待者同时两个 WaitForNextTickAsync 抛 InvalidOperationException
不漂移周期从上一个 tick 计算，不是从循环体结束计算（对比 Task.Delay 循环）
替代System.Threading.Timer（回调重叠、async void）、System.Timers.Timer、Task.Delay 循环

ArrayPool 模式

byte[] buf = ArrayPool<byte>.Shared.Rent(minimumLength);   // 返回 ≥ 请求长度、内容【脏】的数组
try
{
    // 只用 buf.AsSpan(0, n) / buf.AsMemory(0, n)，别信 buf.Length
}
finally
{
    ArrayPool<byte>.Shared.Return(buf);                      // clearArray: true 若含敏感数据
}
// 规则：Rent/Return 配对；Return 后不得再用；不要 Return 不是 Rent 来的数组；小缓冲（≤ 几百字节）优先 stackalloc

Pipelines 最小骨架

var reader = PipeReader.Create(stream);          // 也可 new Pipe() 拿 Reader/Writer 两端
while (true)
{
    ReadResult r = await reader.ReadAsync(ct);
    ReadOnlySequence<byte> buf = r.Buffer;
    while (TryParseFrame(ref buf, out var frame)) Handle(frame);   // 切一帧，推进 buf.Start
    reader.AdvanceTo(buf.Start, buf.End);        // consumed=处理到哪, examined=看到哪（没新数据别再叫我）
    if (r.IsCompleted) break;
}
await reader.CompleteAsync();

// 在 ReadOnlySequence 里找分隔符
SequencePosition? pos = buf.PositionOf((byte)'\n');
if (pos != null) { line = buf.Slice(0, pos.Value); buf = buf.Slice(buf.GetPosition(1, pos.Value)); }
// 或 var sr = new SequenceReader<byte>(buf); sr.TryReadTo(out ReadOnlySpan<byte> line, (byte)'\n');
要不要用 Pipelines
自己解析 socket / 长流上的协议帧✅ 用
定长帧、一次读完整个文件、HTTP 已切好❌ Span + ArrayPool 够了
普通业务代码❌ HttpClient / Kestrel / SignalR / gRPC 内部已经在用
