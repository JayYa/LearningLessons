模块：SDK 项目系统  |  速查参考

当你引用两个包，它们各自依赖同一个包但版本不同时，NuGet 按以下四规则决定最终版本。 一个项目只允许一个包的一个版本。

四项解析规则

规则 1

最低适用版本（Lowest Applicable Version）

满足所有约束的最低版本被选中。这是默认的保守策略。

约束 ≥ 2.1，feed 上有 [2.0, 2.2, 2.3] → 选 2.2（满足且最低）
规则 2

浮动版本（Floating Versions）

6.0.* 取最高匹配稳定版。仅项目级别可用，与规则 1 方向相反。

6.0.*，feed 上有 [6.0.0, 6.0.1, 6.0.2] → 选 6.0.2
规则 3 ⭐ 最常用

直接依赖优先（Direct Dependency Wins / Nearest-Wins）

同一子图中，离项目更近的层决定版本。深层传递版本被忽略。

项目
├── PackageRef → B v2.0              ← 直接引用，胜出
└── PackageRef → A v1.0
    └── 依赖 → B ≥ 3.0                    ← 被忽略

结果：用 B v2.0。如果 2.0 < 3.0，发出 NU1605 警告（降级）。项目能编译，但运行时可能炸 MissingMethodException。

用途：这是你主动解决冲突的手段——加一条直接引用即可覆盖任何传递版本。

规则 4

表亲依赖（Cousin Dependencies）

不同子图需不同版本且无直接引用覆盖时，取满足所有约束的最低版本。

项目
├── PackageRef → A v1.0 → 依赖 B ≥ 1.0
└── PackageRef → C v1.0 → 依赖 B ≥ 2.0
                         → 选 B 2.0（同时满足 ≥1.0 和 ≥2.0）

若无交集：报 NU1107 错误，restore 失败。

A → B [1.0, 2.0)      即 ≥ 1.0 且 < 2.0
C → B [2.0, 3.0)      即 ≥ 2.0 且 < 3.0
                      交集为空 → NU1107

诊断码速查

代码含义严重性修复
NU1605 检测到包降级——传递依赖要求高版本，但被更近的依赖覆盖为低版本 ⚠ 警告 加直接引用指向高版本；或确认降级安全
NU1107 版本冲突——两个包对同一依赖的要求无交集 ❌ 错误 加直接引用覆盖冲突，触发规则 3
NU1103 请求的版本在 feed 上不存在 ❌ 错误 检查版本号拼写；检查 NuGet 源配置

调试命令

# 查看完整依赖树（含传递依赖）
dotnet list package --include-transitive

# 只看有过时版本的包
dotnet list package --outdated --include-transitive

# JSON 格式输出（给脚本用）
dotnet list package --include-transitive --format json

最终裁决文件：obj/project.assets.json——restore 的完整结果，记录了"每个包选了哪个版本、为什么"。调试时直接搜包名。

集中包管理（CPM）

多项目仓库用 Directory.Packages.props 统一版本，从源头消除冲突：

文件内容
/Directory.Packages.props <ManagePackageVersionsCentrally>true</...>
<PackageVersion Include="Newtonsoft.Json" Version="13.0.3" />
各 .csproj <PackageReference Include="Newtonsoft.Json" />（不写 Version）
