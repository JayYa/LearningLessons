一句话区分三个生命周期

生命周期创建时机释放时机Autofac 对应
Transient 每次从容器获取时都创建新实例 Scope 结束时（由容器 Dispose） .InstancePerDependency()（默认）
Scoped 每个 Scope 内只创建一次 Scope 结束时 .InstancePerLifetimeScope()
Singleton 首次获取时创建，全应用唯一 容器 Dispose 时（应用关闭） .SingleInstance()

注册速查

基本注册

var services = new ServiceCollection();

// 接口 → 实现
services.AddTransient<IService, MyService>();
services.AddScoped<IService, MyService>();
services.AddSingleton<IService, MyService>();

// 只注册具体类型（不映射到接口）
services.AddTransient<MyService>();
services.AddScoped<MyService>();
services.AddSingleton<MyService>();

// 已有实例（Singleton 专用——你手动控制生命周期）
services.AddSingleton<IService>(new MyService());

工厂注册

// Transient 工厂——每次获取都调用工厂
services.AddTransient<IService>(sp => new MyService(
    sp.GetRequiredService<IDependency>()
));

// Scoped 工厂
services.AddScoped<IService>(sp =>
{
    var dep = sp.GetRequiredService<IDependency>();
    return new MyService(dep, DateTime.Now);
});

// Singleton 工厂——只调用一次（线程安全保证）
services.AddSingleton<IService>(sp =>
{
    var dep = sp.GetRequiredService<IDependency>();
    return new MyService(dep);
});

// ⚠️ 工厂中不要用 async/await！会导致死锁
// ❌ services.AddSingleton(sp => GetAsync(sp).Result);  // 死锁！

TryAdd——不覆盖已有注册

// 只在 IService 尚未注册时才注册
services.TryAddTransient<IService, MyDefaultService>();
services.TryAddScoped<IService, MyDefaultService>();
services.TryAddSingleton<IService, MyDefaultService>();

// 典型场景：框架提供默认实现，用户可覆盖
services.TryAddSingleton<ICache, MemoryCache>();       // 默认
// 用户代码中可以替换：
// services.AddSingleton<ICache, RedisCache>();         // 覆盖

开放泛型注册

// 注册 ILogger<T> 这样的开放泛型
services.AddSingleton(typeof(IRepository<>), typeof(EfRepository<>));

// 使用时：
// var repo = provider.GetRequiredService<IRepository<Order>>();
// 自动解析为 EfRepository<Order>

获取/解析服务

IServiceProvider provider = services.BuildServiceProvider();

// 获取服务（找不到返回 null）
var svc = provider.GetService<IMyService>();

// 获取服务（找不到抛 InvalidOperationException）——推荐
var svc = provider.GetRequiredService<IMyService>();

// 创建 Scope
using (var scope = provider.CreateScope())
{
    var scopedSvc = scope.ServiceProvider.GetRequiredService<IMyService>();
    // Scope 内的 Scoped 服务共享同一实例
}
// using 结束 → scope 释放 → 其中所有 Transient/Scoped 服务 Dispose

生命周期陷阱表

陷阱表现正确做法
Captive Dependency Singleton 注入 Scoped 服务 → Scoped 被"囚禁"，活到应用关闭 Singleton 只依赖 Singleton/Transient；Scoped 服务通过 IServiceScopeFactory 在方法内创建 scope 获取
Transient 注入 Singleton Transient 变成事实上的 Singleton（只创建一次） 用工厂注册代替，或重新审视设计——是不是该用 Scoped？
Transient IDisposable 内存泄漏 容器持有所有 Transient IDisposable 的引用直到 Scope 结束 用工厂模式创建、手动 Dispose；或改用 Scoped 生命周期
根容器解析 Scoped 服务 Scoped 变成 Singleton（没有 Scope 释放它） 始终在 Scope 内解析 Scoped 服务
DI 工厂中调用 .Result 死锁 保持工厂同步；需要异步初始化时用 IHostedService

解析流程图

请求 IOrderService 实例
│
├── 已注册？
│   ├── 否 → GetService 返回 null / GetRequiredService 抛异常
│   └── 是 ↓
│
├── 生命周期？
│   ├── Singleton → 检查缓存 → 有则返回，无则创建 → 缓存 → 返回
│   ├── Scoped    → 检查当前 Scope 缓存 → 有则返回，无则创建 → 缓存到 Scope → 返回
│   └── Transient → 每次都创建新实例 → 返回
│
└── 构造函数注入
    └── 检查构造函数参数 → 递归解析每个参数类型 → 注入 → 完成

Autofac → MSDI 迁移速查

Autofac 写法MSDI 写法
builder.RegisterType<Foo>().As<IFoo>()services.AddTransient<IFoo, Foo>()
.InstancePerDependency()AddTransient<T>()（也是默认）
.InstancePerLifetimeScope()AddScoped<T>()
.SingleInstance()AddSingleton<T>()
builder.RegisterModule(new MyModule())services.AddXxx() 封装成扩展方法
Assembly ScanningMSDI 不支持，用 Scrutor 或 Autofac 替换容器
Property InjectionMSDI 不支持，只支持构造函数注入
Decorator Pattern用 Scrutor 的 .Decorate<T>()，或手动工厂
💡 MSDI 没有的，用 Scrutor 补：MSDI 故意做得极简——没有程序集扫描、没有装饰器、 没有基于约定的注册。第三方库 Scrutor 是 MSDI 的"官方半支持"扩展，提供 .Scan()、.Decorate() 等。 如果你需要 Autofac 的高级功能，也可以直接替换容器——Autofac、Lamar、Simple Injector 都能接在 IServiceCollection 上面。
