模块：SDK 项目系统  |  速查参考

两种迁移路径

路径 A：自动化（推荐）

dotnet tool install -g upgrade-assistant
upgrade-assistant upgrade MyProject.csproj

交互式，自动转格式 + 迁移依赖

路径 B：手动（理解本质）

四步手迁，适合项目少、想彻底理解变化

手动迁移四步

创建 SDK 风格骨架

dotnet new classlib -n TempLib -f net9.0

打开生成的 TempLib.csproj，复制内容作为起点。控制台应用记得改 <OutputType>Exe</OutputType>。

替换 csproj 内容

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net9.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
</Project>

WPF 项目加 <UseWPF>true</UseWPF>，WinForms 加 <UseWindowsForms>true</UseWindowsForms>。

迁移依赖（最容易出错）

只迁移你真正 using 的顶层包。传递依赖由 NuGet 自动解析，不要手动搬。
把 packages.config 里每个包都转成 PackageReference。旧格式会把传递依赖也列进去——那些是"幽灵依赖"。

packages.config 到 csproj 的对应关系：

packages.config.csproj
<package id="Newtonsoft.Json" version="13.0.1" targetFramework="net48" /> <PackageReference Include="Newtonsoft.Json" Version="13.0.1" />

清理旧文件

  • 删除 packages.config
  • 删除 Properties/AssemblyInfo.cs（SDK 自动生成程序集属性）
  • 删除所有 <Compile Include="..." />
  • 删除所有 <Reference Include="System.*" />
  • 删除 <ProjectGuid> 块

AssemblyInfo → csproj 属性

旧 AssemblyInfo.cs新 csproj 属性
[assembly: AssemblyVersion("1.2.3")]<Version>1.2.3</Version>
[assembly: AssemblyCompany("Acme")]<Company>Acme</Company>
[assembly: AssemblyDescription("...")]<Description>...</Description>
[assembly: InternalsVisibleTo("X.Tests")]<InternalsVisibleTo Include="X.Tests" />

Framework 专属 API 替代

旧 API（不可迁移）替代方案
System.Web.dllMicrosoft.AspNetCore.*
HttpContext.CurrentIHttpContextAccessor（DI 注入）
ConfigurationManagerIConfiguration（Microsoft.Extensions.Configuration）
System.Drawing（服务端）SkiaSharp / SixLabors.ImageSharp
AppDomainAssemblyLoadContext
Remoting / WCF（服务端）gRPC / CoreWCF

多目标支持

<PropertyGroup>
  <!-- 注意是复数 TargetFrameworks，用分号分隔 -->
  <TargetFrameworks>net48;net9.0</TargetFrameworks>
</PropertyGroup>

条件编译：#if NET48 / #if NET9_0（SDK 自动定义这些符号）。

验证清单

  • dotnet restore 成功
  • dotnet build 0 error 0 warning
  • dotnet list package --include-transitive 显示的依赖数量合理
  • dotnet test 全部通过

常见坑

问题原因修复
NU1504 / restore 报错 packages.config 和 PackageReference 共存 删除 packages.config
编译时找不到类型 迁移时漏掉了某个直接依赖 回到旧 packages.config 确认哪些是顶层包
NU1605 大量出现 pass 了"幽灵依赖"进来，版本冲突 删掉非直接依赖的 PackageReference
