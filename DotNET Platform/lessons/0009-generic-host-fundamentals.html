第 9 课：Generic Host——把 DI、配置、日志串起来的那个对象

模块：Host 模型（1/2） |  预计阅读/练习时间：25 分钟

前 5 课你分别学了 DI 容器、配置管道、Options 模式。它们各自都是独立的 NuGet 包，理论上你可以手工 new ServiceCollection()、 手工 new ConfigurationBuilder()、手工把它们接起来——但没人这么做。 现代 .NET 有一个对象专门负责"把这些全部接起来，再管好启动和关闭"：IHost。

Framework 4.8 时代，这个角色被分散在 Global.asax 的 Application_Start、Windows Service 的 ServiceBase.OnStart/OnStop、控制台程序的 Main 里——每种程序类型一套。Generic Host 把它们统一了： 控制台、Worker、ASP.NET Core、WPF，都用同一个 Host。

  • 理解 Host 是什么：一个封装了 DI + 配置 + 日志 + 生命周期的容器对象
  • 掌握 Host.CreateApplicationBuilder() 默认帮你做了什么（以及和旧的 CreateDefaultBuilder 的区别）
  • 区分 Host 配置和应用配置——DOTNET_ENVIRONMENT 是怎么被读到的
  • 亲手搭一个最小控制台应用，拥有和 ASP.NET Core 完全相同的 DI/配置/日志基础设施（任务目标之一）

Framework 4.8 vs 现代 .NET：谁负责"启动"

Framework 4.8现代 .NET（Generic Host）
Web 应用启动 Global.asax → Application_Start，由 IIS 触发 Host.CreateApplicationBuilder(args) → Build() → Run()
——所有程序类型同一套
Windows 服务 继承 ServiceBase，重写 OnStart/OnStop；或用 TopShelf
控制台 Main 里自己 new 一切，自己处理 Ctrl+C
DI / 配置 / 日志接入 各自独立初始化（Autofac 一处、ConfigurationManager 一处、log4net 一处） Host 统一初始化，通过构造函数注入拿到
优雅关闭 Web：AppDomain 回收，几乎不可控；服务：OnStop Host 监听 SIGINT/SIGTERM，按顺序停止所有 IHostedService，默认 30 秒超时

Host 是什么？

官方定义（.NET Generic Host）： "A host is an object that encapsulates an app's resources and lifetime functionality"——具体封装了五样东西： 

IHost
 ├── Services : IServiceProvider        ← DI 容器（第 4–6 课）
 ├── Configuration                      ← 配置根（第 7–8 课）
 ├── Logging                            ← ILogger 工厂（第 11 课）
 ├── IHostedService[]                   ← 后台任务（第 10 课）
 └── 生命周期：StartAsync / StopAsync   ← 启动顺序、优雅关闭

一句话：Host 就是"应用"本身的对象化。以前"应用"是一个进程的模糊概念，现在它是一个可以 StartAsync()、 StopAsync()、可以注入、可以在单元测试里构建的普通对象。

两种 Builder：CreateApplicationBuilder 与 CreateDefaultBuilder

同一个 Host，有两种搭建方式。它们的默认行为完全相同，区别只在代码风格：

旧风格：IHostBuilder（回调式，.NET Core 2.1+）
IHostBuilder builder = Host.CreateDefaultBuilder(args);

builder.ConfigureAppConfiguration((ctx, config) =>
{
    config.AddJsonFile("extra.json", optional: true);
});
builder.ConfigureServices((ctx, services) =>
{
    services.AddHostedService<Worker>();
});
builder.ConfigureLogging(logging =>
{
    logging.AddConsole();
});

IHost host = builder.Build();
host.Run();
新风格：HostApplicationBuilder（属性式，.NET 6+，模板默认）
HostApplicationBuilder builder = Host.CreateApplicationBuilder(args);

builder.Configuration.AddJsonFile("extra.json", optional: true);

builder.Services.AddHostedService<Worker>();

builder.Logging.AddConsole();

IHost host = builder.Build();
host.Run();

新风格是线性的：builder.Configuration、builder.Services、builder.Logging、builder.Environment 都是属性，直接用。旧风格每件事都要套一层 lambda，而且回调的执行顺序被延迟到 Build()——读代码时看不出先后。 新项目用 CreateApplicationBuilder；只有维护老代码或某些第三方库要求回调式时才用 CreateDefaultBuilder （官方建议）。

💡 你在 ASP.NET Core 里见到的 WebApplication.CreateBuilder(args)，就是在 HostApplicationBuilder 之上再加了 Kestrel 和中间件管道。 理解了这一课，ASP.NET Core 系列里 Program.cs 前半段对你就没有秘密了。

CreateApplicationBuilder 默认帮你做了什么

这一节是本课最重要的知识点。第 7 课你手动搭配置管道时那一串 AddJsonFile / AddEnvironmentVariables / AddCommandLine—— CreateApplicationBuilder 全部帮你做了，而且顺序和第 7 课讲的惯例一模一样 （官方列表）： 

Host.CreateApplicationBuilder(args)
 │
 ├─ ContentRoot = Directory.GetCurrentDirectory()
 │
 ├─ Host 配置（决定环境名、内容根等 Host 自身属性）
 │    ├─ 环境变量，前缀 DOTNET_        ← DOTNET_ENVIRONMENT=Development 在这里被读
 │    └─ 命令行参数                     ← --environment Staging 也行
 │
 ├─ 应用配置（你的 IConfiguration，顺序即优先级，最后胜出）
 │    ├─ appsettings.json
 │    ├─ appsettings.{Environment}.json
 │    ├─ User Secrets（仅 Development 环境）
 │    ├─ 环境变量（无前缀）
 │    └─ 命令行参数
 │
 ├─ 日志 Provider
 │    ├─ Console
 │    ├─ Debug
 │    ├─ EventSource
 │    └─ EventLog（仅 Windows）
 │
 └─ DI 容器选项（仅 Development 环境）
      ├─ ValidateScopes  = true         ← 第 6 课的 Captive Dependency 检测
      └─ ValidateOnBuild = true         ← 第 6 课的注册图完整性检测
⚠️ 最后两行是很多人不知道的坑。ValidateScopes / ValidateOnBuild 只在 Development 打开。 这意味着一个 Captive Dependency 在本机跑得好好的（被检测到会直接抛异常——你会修），但如果你本机 DOTNET_ENVIRONMENT 没设成 Development， 它会静默通过，到生产才炸。养成习惯：本机始终以 Development 环境运行。

Host 配置 vs 应用配置

上图里有两层配置，初学最容易混。Host 配置只回答"我是谁、在哪、什么环境"三个问题——它必须在应用配置之前确定， 因为应用配置要靠环境名去决定加载哪个 appsettings.{Environment}.json。

Host 配置应用配置
回答什么EnvironmentName、ContentRoot、ApplicationName你的业务配置：连接串、超时、开关……
来源DOTNET_* 环境变量、命令行appsettings.json、环境变量、命令行……
在哪读builder.Environment（IHostEnvironment）builder.Configuration（IConfiguration）
环境变量示例DOTNET_ENVIRONMENT=StagingDatabase__Timeout=60
// 三种设置环境的方式——效果相同
// 1. 环境变量（推荐：容器 / CI 用这个）
//    DOTNET_ENVIRONMENT=Development
// 2. 命令行
//    dotnet run --environment Development
// 3. 代码（少用，会覆盖前两者）
var builder = Host.CreateApplicationBuilder(new HostApplicationBuilderSettings
{
    Args = args,
    EnvironmentName = Environments.Development,
});

// 读取：
Console.WriteLine(builder.Environment.EnvironmentName);   // "Development"
Console.WriteLine(builder.Environment.IsDevelopment());   // true
Console.WriteLine(builder.Environment.ContentRootPath);   // 当前目录
💡 ASP.NET Core 额外读 ASPNETCORE_* 前缀，所以 Web 项目里常见 ASPNETCORE_ENVIRONMENT。 纯 Generic Host 只认 DOTNET_*。两个都设了时 ASP.NET Core 以 ASPNETCORE_ 为准。

Build() 之后：Host 送你的三个服务

调用 Build() 时，除了你注册的服务，Host 会自动注册三个框架服务 （Framework-provided services），任何类都可以注入：

服务用途下一课会深入
IHostEnvironment 环境名、内容根路径、应用名；IsDevelopment() 等扩展方法 —
IHostApplicationLifetime 三个 CancellationToken：ApplicationStarted / Stopping / Stopped；一个方法 StopApplication()——代码里想优雅退出就调它，别用 Environment.Exit ✅
IHostLifetime 决定 Host "什么时候算启动完、什么信号触发停止"。默认 ConsoleLifetime（监听 Ctrl+C / SIGTERM）；Windows 服务和 systemd 各有替换实现 ✅

动手：最小控制台应用，完整的 DI / 配置 / 日志

这是本系列任务书里明确写的目标之一。整个应用只有三个文件。 

<!-- MinimalHost.csproj -->
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>
  <ItemGroup>
    <!-- 这一个包把 DI、Configuration、Options、Logging 全带进来 -->
    <PackageReference Include="Microsoft.Extensions.Hosting" Version="8.0.*" />
  </ItemGroup>
  <ItemGroup>
    <None Update="appsettings.json" CopyToOutputDirectory="PreserveNewest" />
  </ItemGroup>
</Project>

// appsettings.json
{
  "Logging": { "LogLevel": { "Default": "Information" } },
  "Greeting": { "Name": "World", "Repeat": 2 }
}

// Program.cs
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Logging;
using Microsoft.Extensions.Options;

var builder = Host.CreateApplicationBuilder(args);
// ↑ 到这里：appsettings.json 已加载、Console 日志已就绪、DI 容器已可注册

// 第 8 课：Options 模式
builder.Services.AddOptions<GreetingOptions>()
       .Bind(builder.Configuration.GetSection("Greeting"))
       .ValidateDataAnnotations()
       .ValidateOnStart();

// 第 4 课：注册自己的服务
builder.Services.AddSingleton<Greeter>();

using IHost host = builder.Build();
// ↑ 到这里：IServiceProvider 已构建；Development 环境下已跑 ValidateOnBuild

// "跑一次就退出"的模式：直接从容器取服务用，不调 host.Run()
var greeter = host.Services.GetRequiredService<Greeter>();
greeter.SayHello();
return 0;

// ── 服务 ──
public sealed class GreetingOptions
{
    [System.ComponentModel.DataAnnotations.Required]
    public string Name { get; set; } = "";
    [System.ComponentModel.DataAnnotations.Range(1, 10)]
    public int Repeat { get; set; } = 1;
}

public sealed class Greeter(IOptions<GreetingOptions> options, ILogger<Greeter> logger)
{
    public void SayHello()
    {
        for (int i = 0; i < options.Value.Repeat; i++)
            logger.LogInformation("Hello, {Name}!", options.Value.Name);  // 结构化日志，第 11 课
    }
}

$ dotnet run
info: Greeter[0]
      Hello, World!
info: Greeter[0]
      Hello, World!

$ dotnet run -- --Greeting:Name=Claude --Greeting:Repeat=1     # 命令行覆盖（第 7 课）
info: Greeter[0]
      Hello, Claude!

$ Greeting__Repeat=0 dotnet run                                 # 触发 ValidateOnStart（第 8 课）
Unhandled exception. Microsoft.Extensions.Options.OptionsValidationException:
  DataAnnotation validation failed for 'GreetingOptions' members: 'Repeat' ...
⚠️ 注意 ValidateOnStart 在这个例子里其实没有"提前"触发。它的机制是注册一个 IStartupValidator， 由 IHost.StartAsync() 在启动所有 hosted service 之前调用（Host.cs）。 上面的代码只调了 Build()，没调 Run()/StartAsync()——所以校验是在 Greeter 第一次访问 options.Value 时才跑的（第 8 课讲的"首次构建时校验"）。 结果碰巧一样（都抛 OptionsValidationException），但如果 Greeter 在访问配置之前先做了别的副作用（发邮件、写数据库），差别就出来了。 "跑一次就退"的应用想真正 Fail Fast，要么 await host.StartAsync() 再干活，要么用下一课讲的 IHostedService 模式。

两种运行模式

长驻（服务 / Web / Worker）跑一次就退（CLI 工具、定时任务、迁移脚本）
代码host.Run() 或 await host.RunAsync()host.Services.GetRequiredService<T>() 直接用，然后 return
谁在跑注册的 IHostedService（下一课）你在 Main 里调的那个方法
什么时候退出收到 Ctrl+C / SIGTERM，或代码调 StopApplication()Main 返回
用 Worker 模板？✅ dotnet new worker❌ 用普通控制台模板 + 加 Hosting 包（官方也这么建议）
⚠️ 跑一次就退的模式里，不要在 Main 里直接从根容器解析 Scoped 服务（第 6 课反模式）。 需要 Scoped（比如将来的 DbContext）时：using var scope = host.Services.CreateScope(); scope.ServiceProvider.GetRequiredService<T>()。

检查理解

❓ DOTNET_ENVIRONMENT=Staging 这个环境变量属于哪一层配置，为什么必须先读？
应用配置——因为它和其他环境变量一样被 AddEnvironmentVariables 读取
Host 配置——因为环境名决定要加载哪个 appsettings.{Env}.json
日志配置——因为它决定 Console Provider 的最低日志级别
两层都读——Host 配置读一次，应用配置再读一次覆盖
❓ 一个 Captive Dependency 在同事机器上启动就抛异常，在你机器上却正常运行。最可能的原因？
同事用了 CreateDefaultBuilder，你用了 CreateApplicationBuilder
你的 DOTNET_ENVIRONMENT 不是 Development，容器校验没开
同事安装了 Microsoft.Extensions.Hosting 的更高版本
你的 appsettings.Development.json 覆盖了 Logging 级别
❓ 后台任务完成后想让整个应用优雅退出，应该调什么？
Environment.Exit(0)——最直接，退出码也能控制
host.Dispose()——释放 Host 就等于停止应用
IHostApplicationLifetime.StopApplication()——触发正常关闭流程
throw new OperationCanceledException()——Host 会捕获并停止
❓ Host.CreateApplicationBuilder 和 Host.CreateDefaultBuilder 的本质区别是？
前者默认加载更多配置源，后者只加载 appsettings.json
前者支持 IHostedService，后者只支持 Web 应用
默认行为相同，只是属性式与回调式的代码风格不同
前者是 .NET 8 新增，后者已被标记为 Obsolete

关键术语

Generic Host / IHost
封装 DI 容器、配置、日志、IHostedService 集合和启动/关闭生命周期的对象。NuGet 包 Microsoft.Extensions.Hosting。控制台、Worker、ASP.NET Core、WPF/WinForms 都可以用同一个 Host。
HostApplicationBuilder
Host.CreateApplicationBuilder(args) 返回的属性式 Builder（.NET 6+，模板默认）。.Configuration、.Services、.Logging、.Environment 都是属性，线性配置。推荐用于新项目。
IHostBuilder / CreateDefaultBuilder
回调式的旧 Builder（ConfigureServices(...)、ConfigureAppConfiguration(...)）。默认行为与新 Builder 相同，仍然完全支持，用于维护老代码。
Host 配置 vs 应用配置
Host 配置决定环境名、内容根、应用名，来自 DOTNET_* 环境变量和命令行，必须先读。应用配置是你的业务配置（IConfiguration），加载哪个 appsettings.{Env}.json 取决于 Host 配置里的环境名。
IHostEnvironment
Host 自动注册的服务，暴露 EnvironmentName、ContentRootPath、ApplicationName 和 IsDevelopment() 等判断方法。
IHostApplicationLifetime
Host 自动注册的服务。三个 CancellationToken（ApplicationStarted / ApplicationStopping / ApplicationStopped）用于挂接生命周期事件；StopApplication() 是代码中触发优雅关闭的正确方式（不要用 Environment.Exit）。
IHostLifetime
决定 Host 何时算启动完成、什么外部信号触发停止。默认 ConsoleLifetime（Ctrl+C / SIGTERM）；Windows 服务用 WindowsServiceLifetime，systemd 用 SystemdLifetime。最后注册的胜出。
ContentRoot
应用查找 appsettings.json 等内容文件的基准目录，默认 Directory.GetCurrentDirectory()——注意是"当前工作目录"而不是 exe 所在目录，作为 Windows 服务运行时这是常见坑（下一课讲）。
