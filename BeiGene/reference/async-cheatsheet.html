async / await
＋ 为什么 .Result 会要命

压缩自 Lesson 09。面试前 10 分钟只看这一页。

0 · 一句话判据

await 不创建线程——它把方法剩下的部分登记成一个回调，然后把线程还回去。

异步 ≠ 多线程
  await IO      → 等待期间进程内零线程     （省线程，提吞吐）
  Task.Run CPU  → 等待期间实打实占一个线程 （挪走活，不省线程）

服务端用 async 不是为了单请求更快（其实略慢），
而是为了把「吞吐 = 线程数 ÷ 单请求耗时」这个上限拆掉。

1 · 编译器生成了什么

生成物作用
<WorkAsync>d__0struct，实现 IAsyncStateMachine。是 struct 才能让不挂起的路径零堆分配
MoveNext()原方法体被切成若干段的 switch，每次唤醒接着跑
AsyncTaskMethodBuilder造出并最终完成你返回的那个 Task
 
字段清单（反射打出来就是这四五个）：
  <>1__state       int      跑到第几段（-1 = 正在跑，0 = 停在第一个 await）
  <>t__builder     builder  负责完成返回的 Task
  <>4__this        Demo     实例方法才有
  <s>5__1          你的局部变量  ← 跨越 await，所以从栈搬进状态机
  <>u__1           TaskAwaiter   await 的是 awaiter，不是 Task

2 · await 那一行 = 四步（背下来）

var awaiter = x.GetAwaiter();
if (awaiter.IsCompleted)          // ① 已完成？（缓存命中 / 同步返回）
    result = awaiter.GetResult(); // ② 一步不停继续跑，零分配
else
{
    awaiter.OnCompleted(MoveNext);// ③ 存 state，登记回调
    return;                       //    线程立刻还给线程池
    // ④ IO 完成后，另一个线程再次调 MoveNext，从这里接着跑
}

第 ③④ 步就是「await 之后换线程」的全部解释，也是 Monitor 跨不过 await 的根因（Monitor 认线程，谁进的谁出）。

3 · .Result / .Wait() 的两种死法

环境同步上下文后果
经典 ASP.NET / WPF / WinForms有，且同时只放一个线程死锁：续接等上下文，上下文等续接
ASP.NET Core / 控制台没有不死锁，但一个请求吃两个线程 → 线程池饥饿
 
死锁三条件（缺一不可，去掉任一条都能解开）：
  ① await 默认捕获同步上下文，承诺续接回去跑
  ② 该上下文同时只允许一个线程
  ③ 唯一的位置正被 .Result 阻塞占着
正解是破 ③（调用方改 await），不是破 ①（ConfigureAwait）。
线程池饥饿的症状画像（面试里直接背这三条）

① 接口整体变慢 ② CPU 却很低 ③ 线程数缓慢上涨。
CPU 低 + 全站慢 = 先查线程池。慢的往往不是出问题的那个接口——线程池是全进程共用的。
修法是把链路一路改 async，不是调大最小线程数（那只是把问题推后）。

4 · 硬规则

规则为什么
async 一路到底，中间不要 .Result / .Wait()Once you go async, all of your callers SHOULD be async——半异步比全同步还糟
不写 async void（UI 事件处理器除外）没有 Task 承载异常 → 未处理异常 → 掀掉进程，调用方 catch 不到
类库写 ConfigureAwait(false)，应用代码不写类库不知道调用方环境；应用代码常常需要那个上下文
await Task.WhenAll(...)，不用 Task.WaitAllWait 阻塞，When 不阻塞——一个字母的差别
CancellationToken 一路透传Cancellation is cooperative in .NET，断一环就失效
高频且常同步完成的方法可用 ValueTask省掉 Task 分配；但只能 await 一次，不能存起来复用

5 · 真异步 vs 假异步（判据：等待时占不占线程）

真异步假异步
await db.ToListAsync()GetDataAsync().Result（吃两个线程）
await File.ReadAllTextAsync()await Task.Run(CPU 计算)（活没省，只是挪了）
await Task.Delay(n)（计时器）Thread.Sleep(n)（线程被按住睡）
await Task.WhenAll(...)Task.WaitAll(...)
—list.ForEach(async x => ...) → lambda 是 async void，一个都不等

题骨架
