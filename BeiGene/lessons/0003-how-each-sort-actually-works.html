一、排序只有两个动作

不管什么排序算法，它能做的事情只有两件：

  1. 比较两个数，问「谁大」；
  2. 移动某个数到另一个位置。

所以所有排序算法的区别，只在于「用什么策略减少比较和移动的次数」。最笨的办法是每个数和每个数都比一遍（n² 次），聪明的办法都是想尽办法让一次比较能排除掉一大片可能性。

记住这一句就够了

n² 的算法（插入、冒泡、选择）和 n log n 的算法（快排、堆排、归并）的分界线是：前者每次比较只解决「这两个数谁在前」，后者每次比较能一口气决定「一大批数在另一大批数的哪一边」。下面四个动画，你会亲眼看到这个差别。

二、插入排序：像理扑克牌

一句话：左手已经理好一叠有序的牌，右手每次抽一张新牌，从右往左比，找到位置插进去。

它是四个里最好懂的，也是其它三个的对照组——先看懂它「笨」在哪，才能体会另外三个「聪明」在哪。

static void InsertionSort(int[] a)
{
    for (int i = 1; i < a.Length; i++)
    {
        int v = a[i], j = i - 1;
        while (j >= 0 && a[j] > v) { a[j + 1] = a[j]; j--; }  // 比 v 大的都往右让
        a[j + 1] = v;                                         // 让出来的空位就是它的位置
    }
}

笨在哪：新牌可能要一路挪到最左边，挪 n 次。n 张牌 → 最坏 n² 次移动。

但它有一个杀手锏：如果数据本来就接近有序，每张牌几乎不用挪，时间接近 O(n)——而且它常数极小、对 CPU 缓存友好。这就是为什么 .NET 的 Array.Sort 在区间只剩 16 个元素时会切回插入排序（Lesson 02 第 2 节那条规则，现在有画面了）。

三、快速排序：选个标杆，分两堆

一句话：随便挑一个数当标杆，把比它小的全赶到它左边、比它大的全赶到右边；然后左右两堆各自再来一遍。

就这么多。快排没有第二个想法。所有你在 Lesson 02 里看到的复杂东西（三数取中、尾递归消除、小区间切插排）全是优化，不是原理——原理就是上面这一句。

为什么这样就能排好序？

关键在于分区做完的那一刻：标杆左边所有数都 ≤ 它，右边所有数都 > 它。那么不管左右两边内部怎么乱，标杆已经站在它最终该在的位置上了，永远不用再动。每做一次分区，就有一个数被永久钉死。做 n 次，全部钉死 → 排好了。

动画里绿色的柱子就是「已经钉死、再也不会动」的数。盯着绿色柱子一根根出现，快排就懂了。

最简版的代码——先把这 14 行背熟，再谈优化：

static void QuickSort(int[] a, int lo, int hi)
{
    if (lo >= hi) return;              // 0 个或 1 个数，天然有序
    int p = Partition(a, lo, hi);
    QuickSort(a, lo, p - 1);           // 左半堆，不含标杆
    QuickSort(a, p + 1, hi);           // 右半堆，不含标杆
}

static int Partition(int[] a, int lo, int hi)
{
    int pivot = a[hi];                 // 就拿最后一个当标杆
    int i = lo - 1;                    // i = 「小值区」的最后一格
    for (int j = lo; j < hi; j++)
        if (a[j] <= pivot) Swap(a, ++i, j);   // 小的就并进小值区
    Swap(a, ++i, hi);                  // 标杆归位
    return i;                          // 它的最终下标
}

i 那个变量是唯一需要想一下的地方：i 始终指着「已确认比标杆小的那一段」的最后一格。每发现一个小的，就把它换到 i+1，小值区就长一格。

扩展 · 它什么时候会变慢

如果每次挑的标杆都刚好是当前最小或最大的数，那么「两堆」就变成了「空的一堆 + 剩下全部」，一次只钉死一个数，退化成 O(n²)。什么输入会触发？拿末尾当标杆时，输入本来就已经排好序——最常见的真实场景，偏偏最糟。
解决办法就是别老拿末尾：随机挑一个，或者拿头/中/尾三个数的中位数。这就是 Lesson 02 里「三数取中」那行代码存在的全部理由。

四、堆排序：把数组当成一棵树

堆排序难懂的原因通常不是算法本身，而是「堆」这个词没被讲清楚。所以先说堆。

堆是什么：一个约定，不是一种新数据结构

堆就是一个普通数组。所谓「堆」只是我们对这个数组加了一条读法约定和一条大小约定：

  • 读法约定：把 0 号元素看成树根，i 号元素的两个孩子是 2i+1 和 2i+2（反过来，i 的父亲是 (i−1)/2）。数组一个字节都没变，只是换了个看法。
  • 大小约定：每个父节点都 ≥ 它的两个孩子（这叫大顶堆；反过来是小顶堆）。

这两条约定带来的唯一好处，也是堆存在的全部意义：根（0 号元素）一定是全场最大值，取它只要 O(1)。

注意：堆只保证「上下」，不保证「左右」

父 ≥ 子，但兄弟之间谁大谁小完全没有规定，第 3 层的某个数也完全可能比第 2 层另一支的数大。堆是「半有序」的——它只花力气维护「谁是最大」这一件事，所以才便宜。想不通堆的人，多半是误以为堆是完全有序的。

唯一的操作：下沉（siftDown）

堆只需要一个动作：某个节点的值太小、不配当爹了，就让它和「较大的那个孩子」交换，一路往下沉，直到它比孩子都大（或者沉到底）。

有了下沉，堆排序就是两步：

  1. 建堆：从最后一个有孩子的节点开始，往前对每个节点执行一次下沉。做完，整个数组就满足堆约定了。
  2. 反复取最大：把根（最大值）和数组末尾交换 → 最大值就位；把堆的范围缩小 1（末尾那个不再属于堆）；新根不合格，下沉修复。重复 n−1 次。

下面用 5 个数看（树形视图，红色是根，绿色是已经踢出堆、就位的数）：

static void HeapSort(int[] a)
{
    int n = a.Length;
    for (int i = n / 2 - 1; i >= 0; i--) SiftDown(a, i, n);   // 1. 建堆

    for (int end = n - 1; end > 0; end--)                     // 2. 反复取最大
    {
        Swap(a, 0, end);                                      // 最大值换到末尾就位
        SiftDown(a, 0, end);                                  // 堆缩小到 end，修复新根
    }
}

static void SiftDown(int[] a, int i, int size)
{
    while (true)
    {
        int l = 2 * i + 1, r = 2 * i + 2, big = i;
        if (l < size && a[l] > a[big]) big = l;                // 和左孩子比
        if (r < size && a[r] > a[big]) big = r;                // 和右孩子比
        if (big == i) return;                                 // 已经比孩子都大，沉到位了
        Swap(a, i, big);
        i = big;                                              // 继续往下沉
    }
}

两个值得记住的点：

  • 为什么建堆从 n/2 - 1 开始？因为下标 ≥ n/2 的节点全都是叶子（没有孩子），叶子天然满足堆约定，不用管。
  • 为什么不需要额外内存？因为「树」是想象出来的，数据始终躺在原来那个数组里。这是堆排序相对归并排序的最大优势，也是 .NET 拿它给快排兜底的原因——快排最坏会 O(n²)，那就在递归太深时切成堆排，最坏也是 O(n log n)，而且不多占内存。
扩展 · 堆真正的用处不是排序

面试里堆更常出现在「不排序」的场合：只要「随时能拿到最大/最小的那个」，就用堆——Top-K、优先级队列、定时任务调度、多路归并挑队头。Lesson 02 第 4 节的 Top-K 小顶堆和第 5 节外部排序的多路归并，用的就是这里这个 SiftDown，只是包在 .NET 的 PriorityQueue 里而已。看懂这一节，那两节自动就通了。

五、归并排序：两段有序，合起来很容易

一句话：把两段各自有序的数据合成一段有序的，非常容易——只要反复比两段的队头，小的先出。所以：先一路对半切到只剩一个数（一个数天然有序），再一层层合回来。

它和快排正好相反：快排的力气花在「分」上（分完就不用合），归并的力气花在「合」上（切是无脑对半切）。这一句对比说给面试官听，很加分。

static void MergeSort(int[] a, int[] buf, int lo, int hi)
{
    if (lo >= hi) return;
    int mid = lo + (hi - lo) / 2;
    MergeSort(a, buf, lo, mid);           // 左半排好
    MergeSort(a, buf, mid + 1, hi);       // 右半排好

    for (int t = lo; t <= hi; t++) buf[t] = a[t];   // 拷一份到临时数组
    int i = lo, j = mid + 1;
    for (int k = lo; k <= hi; k++)                  // 两个队头比大小，小的先出
    {
        if (i > mid)            a[k] = buf[j++];    // 左边空了
        else if (j > hi)        a[k] = buf[i++];    // 右边空了
        else if (buf[i] <= buf[j]) a[k] = buf[i++]; // 相等时取左边 → 稳定
        else                    a[k] = buf[j++];
    }
}
这一节直接接上 Lesson 02 的外部排序

盯着合并那一步：任何时刻，内存里真正需要的只是两段的「队头」而已。那么如果这两段不在内存里、而是躺在磁盘上的两个文件呢？照样能合——每段只读一个数进来。
这就是外部归并排序的全部秘密：把「两段」换成「K 段文件」，把「比两个队头」换成「用堆在 K 个队头里挑最大」。Lesson 02 第 5 节那一大段代码，内核就是上面这十行。反过来说，快排和堆排都做不到这件事——它们要求随机访问任意位置，磁盘上做不了。
