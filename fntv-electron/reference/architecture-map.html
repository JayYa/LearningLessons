fntv-electron 仓库地图

v2.6.2（commit bb30d12）· 全仓约 12,800 行 · 速查用

一句话架构：这个 app 不自带前端。它开一个 Electron 窗口去加载 飞牛的远程 Web UI，再用 preload 脚本往那个页面里注入按钮和行为； 真正的重活（调 API、拉起 mpv、同步进度）全在主进程。

进程归属速查

目录进程职责
src/main/main应用入口、窗口、托盘、IPC handler、生命周期
src/modules/main被主进程 import 的业务模块（API、配置、播放器、日志）
src/preload/preload注入远程页面的桥接层，能同时碰 Node 和 DOM
resource/login/renderer唯一的本地页面（登录页），走 file: 协议
src/modules/proxy/Go独立编译的 sidecar 进程，非 TypeScript
判定口诀：能 import { app, BrowserWindow } from 'electron' 的是主进程； 能同时用 fs 和 document 的是 preload； 只能用 document、连 require 都没有的是 renderer。

路径 A：新增一个播放器

src/modules/players/ 是一个标准的 Abstract Factory + Registry。 只有 4 个文件，加一个播放器要动 3 处：

players/
├── types.ts    ← ① enum PlayerType 里加一项
│                 （BasePlayer 抽象类也在这，定义你要实现什么）
├── factory.ts    PlayerFactory：registry 查表建实例，无需改动
├── index.ts    ← ③ export 你的新类（否则不会被加载/注册）
└── impl/
    └── mpv.ts  ← ② 照它写 impl/yours.ts
                   文件末尾 PlayerFactory.registerPlayer(...) 是注册动作

BasePlayer 要求你实现的全部内容（只有 3 个方法）：

abstract playList(infos: PlayItem[], pos: number, args?: string[]): Promise<boolean>;
abstract stop(): void;
abstract isPlaying(): boolean;

基类已经白送你的：getStatus()、emitEvent()、 updateGlobalStatus()、getFnApi()。

已知的硬编码点：media.ts:380 写死了 createPlayer(PlayerType.MPV, playConfig)。 新播放器要真正可用，必须让这里能选类型 —— 这本身就是一个值得提的 PR。

PlayStatusData —— 全链路传递的载荷：

{ itemGuid: string; ts: number; duration: number; percentage: number }
线索：media.ts:136 和 :187 各有一行被注释掉的 // if (…percentage > 90)。这几乎肯定是「看完自动标记已看」的半成品。 你说想做的「某集播放完成状态同步」，起点就在这两行。

两个陷阱。 ① .trellis/spec/ 里混着大量 Trellis 模板残留 —— database.md、pagination.md、react-pitfalls.md： 本项目既没有数据库也没有 React，别照搬。 ② git-conventions.md 让你跑 npm run typecheck 和 npm run lint，但 package.json 里没有这两个脚本。 实际可用的只有 npm run compile 和 npm test。
