第 1 课：SDK 风格项目系统

模块：SDK 项目系统  |  预计阅读/练习时间：15 分钟

如果你来自 .NET Framework 4.8，打开现代 .NET 项目文件的第一反应可能是： "这个 csproj 怎么只剩 5 行了？" 这是你在现代 .NET 中遇到的第一块基石，也是最直观的变化。

为什么这很重要？

  • 现代 .NET 项目文件 简洁 10–50×，靠约定而非配置
  • packages.config 已死——PackageReference 统治一切
  • 共享配置（Directory.Build.props）替代复制粘贴
  • 每个后续模块（DI、配置、日志）都依赖 SDK 风格项目中的 NuGet 包引用

对比：Framework 4.8 vs 现代 .NET

这是一模一样的控制台应用的项目文件，左右对比：

.NET Framework 4.8
<?xml version="1.0" encoding="utf-8"?>
<Project ToolsVersion="15.0"
  xmlns="http://schemas.microsoft.com/
    developer/msbuild/2003">
  <Import Project=
    "$(MSBuildExtensionsPath)\
    $(MSBuildToolsVersion)\
    Microsoft.Common.props" />
  <PropertyGroup>
    <Configuration>Debug</Configuration>
    <Platform>AnyCPU</Platform>
    <ProjectGuid>
      {A1B2C3D4-E5F6-7890-ABCD-EF1234567890}
    </ProjectGuid>
    <OutputType>Exe</OutputType>
    <AppDesignerFolder>
      Properties
    </AppDesignerFolder>
    <RootNamespace>
      MyApp
    </RootNamespace>
    <AssemblyName>MyApp</AssemblyName>
    <TargetFrameworkVersion>
      v4.8
    </TargetFrameworkVersion>
    <FileAlignment>512</FileAlignment>
  </PropertyGroup>
  <PropertyGroup
    Condition="'$(Configuration)|
    $(Platform)'=='Debug|AnyCPU'">
    <DebugSymbols>true</DebugSymbols>
    <DebugType>full</DebugType>
    <Optimize>false</Optimize>
  </PropertyGroup>
  <ItemGroup>
    <Reference Include="System"/>
    <Reference Include="System.Core"/>
    <Reference Include="System.Xml"/>
  </ItemGroup>
  <ItemGroup>
    <Compile Include="Program.cs" />
    <Compile Include="Properties\
      AssemblyInfo.cs" />
  </ItemGroup>
  <Import Project=
    "$(MSBuildToolsPath)\
    Microsoft.CSharp.targets" />
</Project>
现代 .NET (net9.0+)
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net9.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>

</Project>

现代版本没有 GUID、没有程序集引用列表、没有逐个列举 .cs 文件、没有 Debug/Release 配置块。SDK 自动推断一切。

💡 核心原则：约定优于配置。SDK 说"默认把项目里所有 *.cs 都编译"，你就不用写 <Compile Include="..." />。文件系统 就是 项目结构。

三大关键变化

1. PackageReference 替代 packages.config

packages.config
<?xml version="1.0"?>
<packages>
  <package id="Newtonsoft.Json"
    version="13.0.1"
    targetFramework="net48" />
  <package id="Serilog"
    version="2.10.0"
    targetFramework="net48" />
</packages>
PackageReference（写在 csproj 中）
<ItemGroup>
  <PackageReference
    Include="Newtonsoft.Json"
    Version="13.0.1" />
  <PackageReference
    Include="Microsoft.Extensions.Hosting"
    Version="9.0.0" />
</ItemGroup>

优势：

  • 包里嵌套的依赖自动传递解析（你引用 A，A 依赖 B 和 C——你不用管）
  • 多个项目共享依赖时，用 Directory.Packages.props 统一管理版本
  • dotnet restore 替代 NuGet.exe 手动还原

2. ImplicitUsings —— 告别 using 地狱

Framework 4.8 中你每个文件开头都要写：

using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;
using System.Threading.Tasks;

现代 .NET 开启 <ImplicitUsings>enable</ImplicitUsings> 后，编译器根据 SDK 类型自动导入常用命名空间。控制台应用默认获得 System、System.Linq、System.Threading.Tasks 等。你打开 obj/Debug/net9.0/ 下的 .GlobalUsings.g.cs 就能看到生成了什么。

⚠️ Framework 用户的常见困惑：你可能会在教程里看到 using System; 没写但代码能编译——不是魔法，是 SDK 帮你 implicit 了。你仍然可以显式写 using。

3. 共享配置：Directory.Build.props

如果解决方案有 20 个项目，每个都写 <Nullable>enable</Nullable> 很蠢。在仓库根目录放一个 Directory.Build.props，MSBuild 会自动向上查找并导入：

<!-- 仓库根目录 /Directory.Build.props -->
<Project>
  <PropertyGroup>
    <TargetFramework>net9.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
  </PropertyGroup>
</Project>

之后每个项目的 csproj 可以精简到：

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
  </PropertyGroup>
</Project>

动手验证

用以下命令亲手创建一个项目，打开 csproj 看看：

dotnet new console -n HelloPlatform
cd HelloPlatform
cat HelloPlatform.csproj     # Windows: type HelloPlatform.csproj
dotnet run

你应该看到 5 行配置 + 一个能跑的控制台。这就是后面所有课程的基础。

检查理解

❓ Framework 4.8 的 csproj 中，哪个东西在现代 .NET 中不再需要？
PackageReference
ProjectGuid
TargetFramework
OutputType

关键术语

SDK 风格项目
以 <Project Sdk="..."> 开头的项目文件格式。自 .NET Core 1.0 引入，现在是唯一推荐的格式。
PackageReference
在 csproj 中以内联方式声明 NuGet 依赖，替代独立的 packages.config 文件。
Directory.Build.props
放置在目录树中的 MSBuild 属性文件，被该目录及其子目录下所有项目自动导入。
